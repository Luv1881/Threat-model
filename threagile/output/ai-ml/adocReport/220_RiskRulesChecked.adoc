Threagile (see https://threagile.io[] for more details) is an open-source toolkit for agile threat modeling, created by Christian Schneider (https://christian-schneider.net[]): It allows to model an architecture with its assets in an agile fashion as a YAML file directly inside the IDE. Upon execution of the Threagile toolkit all standard risk rules (as well as individual custom rules if present) are checked against the architecture model. At the time the Threagile toolkit was executed on the model input file the following risk rules were checked:

== Path-Traversal
[.small]#path-traversal#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | When a filesystem is accessed Path-Traversal or Local-File-Inclusion (LFI) risks might arise. The risk rating depends on the sensitivity of the technical asset itself and of the data assets processed.
| Detection:   | Filesystems accessed by in-scope callers.
| Rating:      | The risk rating depends on the sensitivity of the data stored inside the technical asset.
|===

== Push instead of Pull Deployment
[.small]#push-instead-of-pull-deployment#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | When comparing push-based vs. pull-based deployments from a security perspective, pull-based deployments improve the overall security of the deployment targets. Every exposed interface of a production system to accept a deployment increases the attack surface of the production system, thus a pull-based approach exposes less attack surface relevant interfaces.
| Detection:   | Models with build pipeline components accessing in-scope targets of deployment (in a non-readonly way) which are not build-related components themselves.
| Rating:      | The risk rating depends on the highest sensitivity of the deployment targets running custom-developed parts.
|===

== Lateral Movement via Transitive Data Flow Across Trust Boundaries
[.small]#lateral-movement-transitive-access#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Lateral Movement
| Description: | An asset in a low-trust zone communicates to a bridging asset, which in turn communicates to an asset in a high-trust zone. The bridging asset creates a transitive path that can be abused for lateral movement without the attacker ever directly connecting to the high-trust target.
| Detection:   | Assets that receive communication from a low-trust zone AND send communication to a high-trust zone (the bridging pattern), where the high-trust target is more sensitive than the low-trust source.
| Rating:      | High when the destination zone contains strictly-confidential or mission-critical assets.
|===

== Missing Content-Security-Policy Header on Web Entry Point
[.small]#missing-csp-header#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | Web entry points (reverse proxies and web applications) that serve browser-based clients and process authentication tokens without a Content-Security-Policy (CSP) header are vulnerable to XSS-facilitated token theft. An attacker who achieves XSS in the browser can read localStorage/sessionStorage tokens and replay them without any client-side protection if CSP is absent.

| Detection:   | In-scope technical assets with reverse-proxy or web-application technology that process PII data assets and are not tagged with has-csp. The has-csp tag serves as the in-model confirmation that CSP is deployed and verified.

| Rating:      | Medium baseline. Elevated when the application uses long-lived tokens (>1 h TTL) stored in browser-accessible storage, or when no WAF is present to block reflected XSS.

|===

== AI/ML - RAG Pipeline Without Input Validation Enabling Prompt Injection
[.small]#ai-ml-prompt-injection-rag-context#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | RAG (Retrieval-Augmented Generation) pipelines that pass user-supplied text to the retrieval step and then into the LLM context without sanitizing or validating inputs are susceptible to prompt injection attacks. An adversary can craft inputs that manipulate the retrieval query, poison the retrieved context, or override the system prompt via retrieved documents containing embedded instructions. Indirect prompt injection through poisoned knowledge-base documents is a growing attack vector against enterprise RAG deployments.

| Detection:   | In-scope technical assets with rag_pipeline technology that are not tagged with has-input-validation.

| Rating:      | High for RAG pipelines that operate in agentic or multi-step workflows where LLM output drives downstream actions. Medium for read-only question-answering pipelines.

|===

== AI/ML - LLM Inference Endpoint Without Input Shield Against Adversarial Inputs
[.small]#ai-ml-adversarial-input-no-shield#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | LLM inference endpoints that receive user-controlled inputs without an input shielding or guardrail layer are vulnerable to a broad class of adversarial inputs including prompt injection, jailbreak attempts, toxicity bypass, and adversarially crafted token sequences that trigger unexpected model behaviour. An input shield (content safety classifier, guardrail model, or structured parsing layer) provides a first line of defence before potentially dangerous inputs reach the core model.

| Detection:   | In-scope technical assets with llm_inference_endpoint technology that are not tagged with has-input-shield.

| Rating:      | High for all internet-facing LLM endpoints. Medium for internal endpoints where all callers are trusted and authenticated employees.

|===

== AI/ML - Multi-Tenant Vector Store Without Access Control
[.small]#ai-ml-vector-store-no-access-control#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | Multi-tenant vector stores that serve multiple organizational units, customers, or user groups without tenant-level access controls allow one tenant to retrieve embeddings and documents belonging to another tenant. In RAG deployments, a missing row-level security or namespace-level isolation layer means that a user in Tenant A can craft retrieval queries that return documents indexed from Tenant B's corpus, constituting a cross-tenant data breach.

| Detection:   | In-scope technical assets with vector_store technology that have multi_tenant set to true and are not tagged with has-access-control.

| Rating:      | High for all multi-tenant vector stores. Critical when tenants include different organizations or when the store indexes confidential or regulated data.

|===

== Lateral Movement via Shared Runtime
[.small]#lateral-movement-shared-runtime#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Lateral Movement
| Description: | Technical assets from different trust zones co-located on the same shared runtime (e.g. container platform, VM host, shared Kubernetes namespace) create a lateral movement path: a compromised low-trust asset on the runtime can escalate to high-trust neighbours without traversing a network boundary.
| Detection:   | Shared runtimes that host technical assets belonging to at least two distinct trust boundaries are flagged.
| Rating:      | Severity depends on the sensitivity gap between the least and most sensitive co-located assets.
|===

== AI/ML - LLM Output Consumed by Custom Code Without Sandboxed Execution
[.small]#ai-ml-llm-output-to-code-execution#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Elevation of Privilege
| Description: | Custom-developed components that receive output from an LLM inference endpoint and execute that output as code, shell commands, or tool invocations without a sandboxed execution environment allow adversarially crafted LLM responses to achieve arbitrary code execution on the host. This pattern is common in agentic systems where the LLM drives a code interpreter, shell executor, or function-calling framework. Prompt injection into the LLM can translate directly into remote code execution if output is executed without sandboxing.

| Detection:   | In-scope technical assets with custom_developed_parts that receive data flows from an LLM inference endpoint and are not tagged with has-sandboxed-execution.

| Rating:      | Critical for components that execute LLM output as code or shell commands. High for agentic systems where the LLM drives tool invocations with external side effects.

|===

|===

== AI/ML - Vector Store Without Encryption at Rest
[.small]#ai-ml-vector-store-no-encryption#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | Vector stores that persist embedding vectors without encryption at rest expose the semantic content of the original documents to anyone with low-level storage access. Although embedding vectors are not plaintext, recent research demonstrates that text can be reconstructed from embeddings with high fidelity using inversion attacks. == AI/ML - ML Training Pipeline With PII Training Data and No Differential Privacy
[.small]#ai-ml-model-inversion-pii-risk#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | ML training pipelines that train on data assets flagged as both training data and PII-containing without applying differential privacy are vulnerable to model inversion and membership inference attacks. An adversary with API access to the deployed model can use gradient-based or output-based techniques to reconstruct training examples and determine whether specific individuals' data was used in training. GDPR's right to erasure (Article 17) and data minimization principle (Article 5) are at risk when PII is memorized in model parameters.

| Detection:   | In-scope technical assets with ml_training_pipeline technology that process data assets with both is_training_data and has_pii set to true, and are not tagged with has-differential-privacy.

| Rating:      | High for all training pipelines processing PII. Critical for health, financial, or biometric data covered by GDPR Article 9 or HIPAA.

|===

== AI/ML - Multi-Tenant LLM Inference Endpoint Without Tenant Isolation
[.small]#ai-ml-shared-inference-multi-tenant#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | LLM inference endpoints that serve multiple tenants from a shared model instance without tenant isolation controls are vulnerable to cross-tenant context leakage. Shared system prompts, shared in-context caching, and shared conversation state can allow one tenant's confidential data or system instructions to leak into another tenant's responses. Prompt injection attacks that manipulate the system prompt are particularly dangerous in multi-tenant deployments because they can affect all tenants sharing the instance.

| Detection:   | In-scope technical assets with llm_inference_endpoint technology that have multi_tenant set to true and are not tagged with has-tenant-isolation.

| Rating:      | High for all multi-tenant LLM inference endpoints. Critical when tenants include different organizations or when the system prompt contains confidential tenant-specific instructions.

|===

== AI/ML - Model Weights Stored in Internet-Accessible Object Storage
[.small]#ai-ml-model-weights-public-access#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | Object storage buckets that are accessible from the internet and contain model weight files represent a direct intellectual property exfiltration risk. Model weights encode the organization's training investment and may memorize sensitive data from training corpora. Publicly accessible weights also enable adversaries to perform offline white-box attacks, including weight extraction, membership inference, and the construction of adversarial examples that bypass production safety guardrails.

| Detection:   | In-scope technical assets with object_storage technology that are internet-accessible and receive data flows from assets tagged is_model_weights, and are not tagged with has-private-acl.

| Rating:      | High for proprietary fine-tuned models. Critical when training data contained confidential or personally identifiable information.

|===

== Missing Network Segmentation
[.small]#missing-network-segmentation#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Elevation of Privilege
| Description: | Highly sensitive assets and/or data stores residing in the same network segment than other lower sensitive assets (like webservers or content management systems etc.) should be better protected by a network segmentation trust-boundary.
| Detection:   | In-scope technical assets with high sensitivity and RAA values as well as data stores when surrounded by assets (without a network trust-boundary in-between) which are of type client-system, web-server, web-application, cms, web-service-rest, web-service-soap, build-pipeline, sourcecode-repository, monitoring, or similar and there is no direct connection between these (hence no requirement to be so close to each other).
| Rating:      | Default is low risk. The risk is increased to medium when the asset missing the trust-boundary protection is rated as strictly-confidential or mission-critical.
|===

== AI/ML - Embedding Service Processing PII Internet-Accessible Without Access Control
[.small]#ai-ml-embedding-service-pii-exposure#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Information Disclosure
| Description: | Embedding services that generate vector representations of text or other data and are both internet-accessible and process PII-containing data assets, without access control, expose personally identifiable information to any actor who can call the embedding API. Embedding APIs receive the raw input text to be embedded, meaning every request contains the source content before it is converted to a vector. An unauthenticated or improperly authorized embedding endpoint is effectively an unauthenticated API for querying raw PII.

| Detection:   | In-scope technical assets with embedding_service technology that process data assets containing PII, are internet-accessible, and are not tagged with has-access-control.

| Rating:      | High for all internet-accessible embedding services processing PII. Critical when the service processes health, financial, or sensitive-category personal data.

|===

== AI/ML - ML Training Pipeline With Custom Code and Unpinned Base Images
[.small]#ai-ml-ml-pipeline-unpinned-dependencies#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | ML training pipelines with custom-developed components that run container images without digest-pinned base images are vulnerable to silent supply-chain substitution. ML training images commonly depend on specific framework versions (PyTorch, TensorFlow, CUDA) that are referenced by mutable tags. If an upstream image publisher is compromised or changes the tag to point to a different layer, all subsequent training runs silently use the substituted image. This can result in backdoored models, exfiltrated training data, or training divergence due to dependency version drift.

| Detection:   | In-scope technical assets with ml_training_pipeline technology that have custom_developed_parts set to true and are not tagged with has-pinned-base-images.

| Rating:      | Medium baseline. Elevated to High when the training pipeline processes confidential or PII-containing training data, or when the resulting models are deployed in safety-critical or regulated systems.

|===

[.small]#dos-risky-access-across-trust-boundary#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Denial of Service
| Description: | Assets accessed across trust boundaries with critical or mission-critical availability rating are more prone to Denial-of-Service (DoS) risks.
| Detection:   | In-scope technical assets (excluding load-balancer) with availability rating of critical or higher which have incoming data-flows across a network trust-boundary (excluding devops usage).

== AI/ML - ML Training Pipeline Without Data Versioning
[.small]#ai-ml-training-data-no-versioning#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | ML training pipelines that do not version training datasets make it impossible to reproduce model training runs, audit what data was used to train a deployed model, or roll back to a known-good dataset after data poisoning is discovered. Without immutable, versioned dataset snapshots, an attacker who modifies training data can silently degrade model behaviour across all future training runs.

| Detection:   | In-scope technical assets with ml_training_pipeline technology that are not tagged with has-data-versioning.

| Rating:      | Medium baseline. Elevated when the training pipeline processes confidential data or when the trained model is deployed in a regulated or safety-critical context.

== AI/ML - LLM Inference Endpoint Internet-Accessible Without Authentication
[.small]#ai-ml-inference-endpoint-no-auth#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Elevation of Privilege
| Description: | LLM inference endpoints that are accessible from the internet without authentication allow any actor to query the model without restrictions. This exposes the organization to unauthorized inference costs, model misuse, content policy violations, and potential exfiltration of system prompts or fine-tuning data through adversarial querying. Unauthenticated LLM endpoints are frequently discovered and abused within hours of exposure.

| Detection:   | In-scope technical assets with llm_inference_endpoint technology that are internet-accessible and not tagged with has-authentication.

| Rating:      | High for all internet-exposed LLM endpoints. Critical when the model has access to proprietary data or is integrated into automated decision-making pipelines.

== AI/ML - LLM Output Used in Custom Code Without Output Validation
[.small]#ai-ml-no-output-validation-before-action#


[cols="h,1",frame=none,grid=none]
|===
| STRIDE:      | Tampering
| Description: | Custom-developed components that receive output from an LLM inference endpoint and act on it without validating the output structure, content, or safety properties allow adversarially crafted LLM outputs to drive unintended downstream actions. In agentic workflows where LLM output is parsed as commands, JSON, code, or tool invocations, missing output validation is a primary enabler of indirect prompt injection, jailbreak-driven privilege escalation, and unintended automation actions.

| Detection:   | In-scope technical assets with custom_developed_parts that receive data flows from an LLM inference endpoint and are not tagged with has-output-validation.

| Rating:      | High for custom components that parse LLM output as commands, code, or structured action plans. Critical in fully agentic workflows with external side effects.
