= STRIDE Classification of Identified Risks
:fn-risk-findings: footnote:riskfinding[Risk finding paragraphs are clickable and link to the corresponding chapter.]

This chapter clusters and classifies the risks by STRIDE categories: In total *79 potential risks* have been identified during the threat modeling process of which *1 in the Spoofing* category, *35 in the Tampering* category, *0 in the Repudiation* category, *24 in the Information Disclosure* category, *3 in the Denial of Service* category, and *15 in the Elevation of Privilege* category.{fn-risk-findings}

If this risk is unmitigated, attackers might be able to exploit risks unseen in this threat model in the identity provider/store that is currently missing in the model.

<<supply-chain-no-dependency-scanning,[.ElevatedRisk]#Elevated: *Supply Chain - Build Pipeline Without Dependency Vulnerability Scanning*: 1/1 unmitigated Risk - Exploitation likelihood is _Likely_ with _High_ impact.#>>::
Known-vulnerable dependencies are the delivery mechanism for the most impactful supply-chain attacks (Log4Shell, Struts RCE, Heartbleed). Without automated scanning, developers are not alerted when a dependency they already use receives a new CVE, and the window of exposure extends until manual discovery.


<<supply-chain-no-sbom,[.ElevatedRisk]#Elevated: *Supply Chain - Build Pipeline Without Software Bill of Materials*: 1/1 unmitigated Risk - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
When a critical CVE is disclosed for a widely-used library, security teams without SBOMs must manually inspect every codebase to determine exposure. This dramatically increases mean-time-to-remediate and may miss affected builds. Without SBOMs, legal obligations for software composition disclosure (EU CRA, FDA) cannot be met.


<<supply-chain-no-sast,[.ElevatedRisk]#Elevated: *Supply Chain - Custom-Developed Application Without Static Analysis (SAST)*: 5/5 unmitigated Risks - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
Undetected injection flaws, insecure deserialization, and cryptographic weaknesses in custom code can lead to full application compromise, data breach, or privilege escalation. The cost to fix vulnerabilities discovered in production is 10–100x higher than fixing them at code-review time.


<<supply-chain-no-code-review,[.ElevatedRisk]#Elevated: *Supply Chain - Source Code Merged Without Mandatory Peer Review*: 1/1 unmitigated Risk - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
Code that bypasses review can introduce vulnerabilities directly to the production path. In multi-developer teams, unreviewed commits are also a vector for insider threats and compromised-account attacks where an attacker uses a stolen token to merge malicious code directly.


<<supply-chain-no-branch-protection,[.ElevatedRisk]#Elevated: *Supply Chain - Source Code Repository Without Branch Protection*: 1/1 unmitigated Risk - Exploitation likelihood is _Likely_ with _High_ impact.#>>::
Unprotected branches allow direct pushes that bypass security controls. A compromised credential can introduce vulnerabilities directly into the production code path without review. History rewrites (force-push) can erase evidence of malicious commits.


<<code-backdooring,[.MediumRisk]#Medium: *Code Backdooring*: 3/3 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _High_ impact.#>>::
If this risk remains unmitigated, attackers might be able to execute code on and completely takeover production environments.

<<container-baseimage-backdooring,[.MediumRisk]#Medium: *Container Base Image Backdooring*: 7/7 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _High_ impact.#>>::
If this risk is unmitigated, attackers might be able to deeply persist in the target system by executing code in deployed containers.

<<missing-build-infrastructure,[.MediumRisk]#Medium: *Missing Build Infrastructure*: 1/1 unmitigated Risk - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to exploit risks unseen in this threat model due to critical build infrastructure components missing in the model.

<<missing-cloud-hardening,[.MediumRisk]#Medium: *Missing Cloud Hardening*: 3/3 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _Very High_ impact.#>>::
If this risk is unmitigated, attackers might access cloud components in an unintended way.

<<missing-waf,[.MediumRisk]#Medium: *Missing Web Application Firewall (WAF)*: 1/1 unmitigated Risk - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to apply standard attack pattern tests at great speed without any filtering.

<<supply-chain-unsigned-container-image,[.MediumRisk]#Medium: *Supply Chain - Container Images Without Cryptographic Signing*: 2/2 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _High_ impact.#>>::
Unsigned images in an untrusted registry or CDN can be substituted for legitimate images, resulting in remote code execution, data exfiltration, or persistent access. Image tampering is particularly dangerous because it affects all deployments that pull the image after the substitution.


<<supply-chain-unpinned-base-images,[.MediumRisk]#Medium: *Supply Chain - Container Platform Running Unpinned Base Images*: 1/1 unmitigated Risk - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
An upstream publisher compromise or a registry-level tag substitution silently delivers a different image. In Kubernetes, re-scheduling a pod without image pull policy Always can use a cached malicious image that bypasses admission controls. Unpinned base images also make builds non-reproducible, hiding regression sources.


<<unchecked-deployment,[.MediumRisk]#Medium: *Unchecked Deployment*: 3/3 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
If this risk remains unmitigated, vulnerabilities in custom-developed software or their dependencies might not be identified during continuous deployment cycles.

<<unchecked-deployment,[.LowRisk]#Low: *Unchecked Deployment*: 3/3 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::

== Information Disclosure
<<exposed-default-credentials,[.HighRisk]#High: *Asset Using Known Default or Hardcoded Credentials*: 1/1 unmitigated Risk - Exploitation likelihood is _Very Likely_ with _High_ impact.#>>::
Any attacker with network access can authenticate using default credentials, exfiltrate all stored data, modify records, or pivot into adjacent systems.


<<missing-csp-header,[.ElevatedRisk]#Elevated: *Missing Content-Security-Policy Header on Web Entry Point*: 1/1 unmitigated Risk - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
An attacker who successfully injects client-side script can exfiltrate authentication tokens, impersonate users, and access all data the victim can access. Without CSP, there is no browser-enforced barrier against inline script execution or data exfiltration.


<<path-traversal,[.ElevatedRisk]#Elevated: *Path-Traversal*: 3/3 unmitigated Risks - Exploitation likelihood is _Very Likely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to read sensitive files (configuration data, key/credential files, deployment files, business data files, etc.) from the filesystem of affected components.

<<server-side-request-forgery,[.ElevatedRisk]#Elevated: *Server-Side Request Forgery (SSRF)*: 8/8 unmitigated Risks - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to access sensitive services or files of network-reachable components by modifying outgoing calls of affected components.

<<unencrypted-communication,[.ElevatedRisk]#Elevated: *Unencrypted Communication*: 4/4 unmitigated Risks - Exploitation likelihood is _Likely_ with _High_ impact.#>>::
If this risk is unmitigated, network attackers might be able to to eavesdrop on unencrypted sensitive data sent between components.

<<accidental-secret-leak,[.MediumRisk]#Medium: *Accidental Secret Leak*: 1/1 unmitigated Risk - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers which have access to affected sourcecode repositories or artifact registries might find secrets accidentally checked-in.

<<missing-vault,[.MediumRisk]#Medium: *Missing Vault (Secret Storage)*: 1/1 unmitigated Risk - Exploitation likelihood is _Unlikely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to easier steal config secrets (like credentials, private keys, client certificates, etc.) once a vulnerability to access files is present and exploited.

<<server-side-request-forgery,[.MediumRisk]#Medium: *Server-Side Request Forgery (SSRF)*: 8/8 unmitigated Risks - Exploitation likelihood is _Likely_ with _Medium_ impact.#>>::
If this risk is unmitigated, attackers might be able to access sensitive services or files of network-reachable components by modifying outgoing calls of affected components.

<<unencrypted-asset,[.MediumRisk]#Medium: *Unencrypted Technical Assets*: 5/5 unmitigated Risks - Exploitation likelihood is _Unlikely_ with _High_ impact.#>>::
If this risk is unmitigated, attackers might be able to access unencrypted data when successfully compromising sensitive components.
